## 1. Краткая характеристика дисциплины (модуля)

Дисциплина (модуль) «Введение в функциональное программирование на языке Scala» ориентирована на подготовку специалистов, способных разрабатывать масштабируемые и надежные программные решения для высоконагруженных систем и обработки больших данных. Освоение курса направлено на формирование компетенции ПК-1, что обеспечивает способность применять математические модели и методы оптимизации для проектирования алгоритмов, а также использовать функциональную парадигму для создания кода, устойчивого к ошибкам и легко поддающегося тестированию (индикаторы ПК-1.1, ПК-1.2, ПК-1.3). Студенты учатся комбинировать объектно-ориентированный и функциональный подходы, что критически важно для ролей Scala-разработчика и Инженера данных (Data Engineer), работающих с современными стеками технологий (Apache Spark, Akka). Содержание дисциплины охватывает ключевые аспекты языка Scala и экосистемы JVM. В первом блоке изучаются основы синтаксиса, система типов, работа с функциями высшего порядка и коллекциями, а также механизмы сопоставления с образцом (pattern matching) и case-классы. Второй блок посвящен технологиям разработки: модульному тестированию (ScalaTest), сборке проектов (Maven) и использованию графических библиотек. Продвинутые темы включают работу с неявными преобразованиями (implicits), составными типами и XML. Особое внимание уделяется многопоточному и распределенному программированию: примитивам синхронизации, безблокировочным алгоритмам, модели акторов и библиотеке Akka, что формирует навыки создания параллельных и асинхронных систем. Для успешного изучения дисциплины обучающимся необходимо: владеть основами объектно-ориентированного программирования (знание Java или C++ будет преимуществом); понимать принципы алгоритмизации и структур данных; иметь базовые знания о многопоточности и работе операционных систем.

Для применения теоретических знаний на практике, а также для развития критического мышления и навыков решения реальных проблем обучающимся предлагаются кейсы, разработанные партнерскими организациями. Примеры кейсов представлены ниже:

**1.** Разработка ETL-пайплаина для обработки потоковых логов с использованием Apache Spark (Scala API) и функциональных подходов Описание: необходимо обработать поток логов событий в мобильном приложении (просмотры, клики) для расчета сессионных метрик: длительность сессии, количество событий, уникальные экраны. Данные поступают в Apache Kafka, а обработка должна быть отказоустойчивой и масштабируемой. Цель: написать на Scala Spark Streaming (или Structured Streaming) job, который: читает данные из Kafka, преобразует сырые JSON-записи в типизированные case-классы, группирует события по session_id, вычисляет метрики с помощью агрегатных функций и immutable преобразований (map, groupBy, agg), и записывает результат в хранилище (HDFS, ClickHouse).

**2.** Построение иммутабельной, чисто функциональной модели для расчёта сложных процентов и графиков погашения кредита Описание: требуется создать библиотеку для финансовых расчётов, которая будет использоваться в нескольких сервисах. Модель должна быть детерминированной, тестируемой и лишённой скрытых побочных эффектов. Основная функция - расчёт аннуитетного платежа и построение полного графика платежей по кредиту. Цель: разработать на Scala набор чисто функциональных методов (функций высшего порядка, рекурсии) и иммутабельных case-классов (LoanTerms, PaymentSchedule). Использовать Either или Validated из библиотеки Cats для обработки ошибок валидации входных данных (отрицательная ставка, неверный срок). Написать property-based тесты (ScalaCheck) для проверки математических инвариантов.

**3.** Создание DSL (предметно-ориентированного языка) на Scala для декларативного описания конфигурации A/B-тестов Описание: Конфигурация A/B-тестов (сплиты, целевые метрики, фильтры аудитории) часто хранится в JSON/YAML и парсится в runtime, что приводит к ошибкам в строках-ключах. Можно создать типобезопасный внутренний DSL на Scala, позволяющий описывать эксперименты на этапе компиляции. Цель: Используя возможности Scala (implicit classes, extension methods, fluent API), разработать DSL, который позволяет в коде писать Experiment("NewButton") split 50 on Metric.ClickRate filter Audience.Region("RU"). Обеспечить компиляционную проверку корректности: существования метрик, корректности процентов сплита. Преобразовывать такое описание в case-класс для дальнейшей обработки.

**4.** Реализация иммутабельных структур данных: односвязный список (List) и бинарное дерево поиска (BST) на Scala Описание: необходимо понять базовые принципы функциональных структур данных, которые не изменяются, а при «изменении» создают новую версию, переиспользуя части старой (persistent data structures). Цель: определить алгебраический тип данных sealed trait MyList[+A] с двумя case- классами: Cons (голова и хвост) и Nil. Реализовать основные функции: map, filter, foldLeft, foldRight с использованием pattern matching и рекурсии. Аналогично реализовать иммутабельное бинарное дерево поиска (sealed trait Tree[+A]) с операциями вставки и поиска.

**5.** Разбор и вычисление арифметических выражений с помощью парсер- комбинаторов (библиотека cats-parse) Описание: требуется написать парсер, который понимает простой язык арифметических выражений с числами, операторами +, -, *, / и скобками, и вычисляет его значение. Цель: Используя библиотеку cats-parse (или стандартный scala.util.parsing.combinator), построить грамматику снизу вверх: парсер для чисел, парсер для множителей (число или выражение в скобках), парсер для слагаемых (цепочка множителей с * и /), парсер для выражений (цепочка слагаемых с + и -). Реализовать вычисление значения прямо в процессе парсинга, получая на выходе Int или Double.

**6.** Разработка простого concurrent кэша с использованием Future и Software Transactional Memory (STM) на основе библиотеки ZIO или Cats Effect Описание: необходимо реализовать потокобезопасный кэш с TTL (временем жизни записей). Кэш будет использоваться из нескольких потоков. Нужно обеспечить согласованность данных и избегать race conditions. Цель: реализовать две версии. Версия 1: на основе Future и synchronized/AtomicReference. Версия 2: на основе STM (ZIO STM или ScalaSTM), используя транзакционную модель для атомарных операций чтения-записи. Сравнить корректность, производительность и сложность кода. Добавить механизм очистки устаревших записей (background fiber/thread).
