## 1. Краткая характеристика дисциплины (модуля)

Дисциплина (модуль) «Углубленное программирование на С/С++» является специализированным модулем, направленным на подготовку специалистов, способных решать задачи высокопроизводительных вычислений и системного программирования. Она ориентирована на выпускников, планирующих карьеру в ролях Разработчика высоконагруженных систем, Инженера по оптимизации и Разработчика встроенного ПО. Освоение дисциплины фокусируется на формировании компетенции ПК-5, что обеспечивает способность разрабатывать, отлаживать и оптимизировать эффективные многопоточные решения на C++ с использованием GPU и FPGA, а также применять методы профилирования для выявления узких мест в коде (индикаторы ПК-5.1, ПК-5.2). Содержание дисциплины структурировано в четыре раздела, последовательно углубляющих навыки работы с низкоуровневыми механизмами. Первый раздел посвящен методам оптимизации кода, работе с аппаратными ресурсами (кэш-памятью процессора) и использованию инструментов профилирования. Второй раздел погружает в низкоуровневое программирование: управление памятью через указатели, использование ассемблерных вставок и битовых операций. Третий и четвертый разделы охватывают разработку многопоточных приложений (синхронизация потоков, мьютексы, семафоры) и реализацию эффективных структур данных и алгоритмов для обработки больших объемов информации, что критически важно для создания масштабируемых систем ИИ. Для успешного изучения дисциплины обучающимся необходимо: владеть базовым синтаксисом языка C/C++; понимать принципы работы операционных систем и архитектуры ЭВМ; знать основы алгоритмизации и структур данных.

**1.** Разработка высокопроизводительного сетевого сервера для обработки RPC- запросов в распределенной системе хранения (аналог YDB) Описание: требуется создать сервер, способный эффективно обрабатывать десятки тысяч одновременных соединений, принимая мелкие RPC-запросы к распределенному кешу или метаданным. Ключевые требования: минимальные задержки, эффективное использование CPU, работа в условиях интенсивного сетевого ввода-вывода. Цель: реализовать асинхронный сервер на C++20, используя системный вызов io_uring для неблокирующего I/O и работы с сетевыми сокетами. Организовать пул потоков (thread pool) для обработки CPU-интенсивных задач. Обеспечить lock-free структуры данных для передачи задач между IO- и worker-потоками. Провести нагрузочное тестирование, измерив RPS (запросов в секунду) и задержки.

**2.** Оптимизация ядра численных вычислений для скоринговой модели (например, градиентного бустинга) с использованием SIMD-инструкций (AVX-512) и метапрограммирования Описание: Продукционная система скоринга должна обрабатывать миллионы заявок в день. Необходимо выжать максимум производительности из инференса ансамбля деревьев, убрав накладные расходы высокоуровневых библиотек и задействовав все возможности современного CPU. Цель: реализовать функцию предсказания на C++ с использованием: 1) Векторизации: ручная развертка циклов и использование intrinsics для инструкций AVX2/AVX-512 для одновременной обработки нескольких заявок. 2) Шаблонного метапрограммирования: генерация специализированного кода для конкретных типов признаков (float, int) на этапе компиляции. 3) Оптимизации доступа к памяти: выравнивание структур данных под кеш-линии. Сравнить производительность с вызовом стандартной библиотеки CatBoost.

**3.** Создание memory-mapped хранилища с persistence для логов транзакций с гарантиями атомарности и консистентности (ACID) Описание: для высокой доступности компонента необходим механизм записи логов или состояния в энергонезависимую память (диск) с минимальными задержками, гарантирующий, что записанные данные не будут повреждены даже при сбое питания (crash consistency). Использование классических файловых операций (fwrite) слишком медленно. Цель: реализовать на C++ циклический буфер (ring buffer), отображенный в память через mmap. Разработать протокол записи с использованием атомарных операций над словами (std::atomic) и принудительного сброса на диск (msync) для обеспечения порядка записи и durability. Протестировать корректность восстановления данных после симуляции сбоя.

**4.** Реализация lock-free очереди (MPSC - Multiple Producers, Single Consumer) с использованием атомарных операций и модели памяти C++ Описание: В высоконагруженном многопоточном приложении несколько потоков-производителей генерируют задачи, а один поток-потребитель их обрабатывает. Использование мьютексов для синхронизации доступа к общей очереди становится узким местом. Цель: реализовать очередь на основе кольцевого буфера, используя только атомарные операции (compare_exchange_strong, load/store с нужным memory_order). Корректно организовать синхронизацию для сценария MPSC, гарантируя отсутствие data race и прогресс. Проверить корректность с помощью thread sanitizer и сравнить производительность с блокирующей очередью (std::queue + std::mutex) под высокой нагрузкой.

**5.** Разработка RAII-обертки для работы с сетевыми сокетами и таймерами в стиле современных C++ (move-семантика, пользовательские литералы) Описание: Работа с низкоуровневыми API сокетов (POSIX) в C чревата утечками ресурсов и сложной обработкой ошибок. Необходимо создать типобезопасные, исключения-безопасные и удобные обертки, управляющие временем жизни ресурсов (сокет, таймер) автоматически. Цель: Разработать классы Socket (с поддержкой TCP) и Timer (на основе timerfd), использующие RAII (получение ресурса в конструкторе, освобождение в деструкторе), запрещающие копирование, но поддерживающие move-семантику. Реализовать методы с использованием современных возможностей C++20 (coroutines для асинхронности - опционально). Добавить пользовательские литералы для удобного задания времени (например, 500_ms).

**6.** Создание простого JIT-компилятора математических выражений с генерацией машинного кода «на лету» Описание: есть необходимость многократно вычислять одну и ту же пользовательскую формулу (например, a*x + b*y) с разными значениями переменных. Интерпретация строки или обход AST на каждом вычислении медленны. Цель: реализовать систему, которая: 1) Парсит строку с выражением в AST. 2) Генерирует по AST машинный код x86-64 (используя, например, библиотеку AsmJit или написание сырых байтов в исполняемую память). 3) Динамически выделяет исполняемую память (mmap с флагом PROT_EXEC), вызывает сгенерированную функцию и возвращает результат. В рамках внутренней системы оценки качества образовательной деятельности по программе обучающимся предоставляется возможность оценивания условий, содержания, организации и качества образовательного процесса по данной дисциплине (модулю). Система оценивания результатов обучения по дисциплине (модулю) Знания, умения и навыки обучающихся при промежуточной аттестации определяются в следующей форме: «отлично» (A), «хорошо» (B), «удовлетворительно» (C), «неудовлетворительно» (D).
