Задача 2: Рекомендательная система на основе матричной факторизации

Условие задачи

Рекомендательные системы анализируют предпочтения пользователей для предложения релевантного контента (фильмов, музыки, товаров). Одним из классических подходов является матричная факторизация, позволяющая выявить скрытые признаки пользователей и объектов на основе известных оценок.

Вам предстоит реализовать алгоритм обучения модели матричной факторизации методом стохастического градиентного спуска (SGD). На вход подаются известные оценки пользователей объектам. Необходимо обучить модель, сохранить её промежуточные состояния для проверки корректности обучения и сделать предсказания для тестовых пар.

Теоретическая справка

Матричная факторизация Модель аппроксимирует матрицу оценок 𝑅 (размера 𝑈 × 𝐼 ) произведением двух матриц латентных факторов:

𝑅 ≈ 𝑃 ⋅ 𝑄𝑇 где 𝑃 — матрица факторов пользователей (𝑈 × 𝐾), 𝑄 — матрица факторов объектов (𝐼 × 𝐾), 𝐾 — размерность латентного пространства.

Предсказание и ошибка Предсказание оценки для пользователя 𝑢 и объекта 𝑖: 𝑟̂𝑢𝑖 = 𝐩𝑢 ⋅ 𝐪𝑖𝑇 Ошибка предсказания для известной оценки 𝑟𝑢𝑖: 𝑒𝑢𝑖 = 𝑟𝑢𝑖 − 𝑟̂𝑢𝑖

Обновление векторов (SGD с L2-регуляризацией) Обновление векторов факторов производится по следующим формулам: 𝐩𝑢 ← 𝐩𝑢 + 𝜂 ⋅ (𝑒𝑢𝑖 ⋅ 𝐪𝑖 − 𝜆 ⋅ 𝐩𝑢) 𝐪𝑖 ← 𝐪𝑖 + 𝜂 ⋅ (𝑒𝑢𝑖 ⋅ 𝐩𝑢old − 𝜆 ⋅ 𝐪𝑖) Важно: При обновлении 𝐪𝑖 следует использовать значение 𝐩𝑢 до его обновления на текущем шаге (𝐩𝑢old).

Задача 3: Классификация текстов (определение тональности отзывов)

Условие задачи

Анализ тональности текстов (sentiment analysis) является ключевой задачей обработки естественного языка. Вам предстоит разработать систему классификации англоязычных отзывов о фильмах на позитивные (1) и негативные (0).

Необходимо реализовать конвейер обработки данных, включающий предобработку текста, векторизацию методом «мешок слов» и обучение наивного байесовского классификатора. Модель должна быть обучена на предоставленной размеченной выборке и применена для предсказания меток на тестовом наборе.

Теоретическая справка

Предобработка текста Для корректной работы моделей машинного обучения текст необходимо привести к единому формату:

 Приведение к нижнему регистру устраняет различия между словами с разным регистром

 Удаление специальных символов оставляет только значимые токены (буквы, цифры, пробелы)

Векторизация CountVectorizer Метод преобразует коллекцию текстов в матрицу частот терминов. Параметр stop_words позволяет исключить часто встречающиеся слова, не несущие смысловой нагрузки.

Наивный байесовский классификатор MultinomialNB — вероятностный классификатор, основанный на теореме Байеса. Эффективен для задач классификации текстов с мешком слов.

Задача 7: Многоагентное обучение с подкреплением (Тактический бой)

Введение

Вам предстоит разработать искусственный интеллект для управления командой из трёх автономных агентов в среде командного боя с частичной наблюдаемостью. Агенты вашей команды (синие) используют единую нейронную сеть с общими весами (parameter sharing), но принимают решения независимо на основе общей карты видимости. Ваше решение будет участвовать в турнире против агентов, разработанных другими участниками. Итоговая оценка зависит от результатов матчей, эффективности боя, координации и стабильности.

Параметры среды

| Параметр | Значение |
| --- | --- |
| Размер карты | 12×12 клеток |
| Команды | 2 (Синие против Жёлтых) |
| Агентов в команде | 3 |
| Максимум шагов | 200 |
| Здоровье агента (HP) | 3 единицы |
| Поле зрения агента | квадрат 5×5 вокруг себя |
| Видимость команды | объединение зон видимости всех живых агентов |
| Количество ловушек | 4 |
| Интервал движения ловушек | каждые 2 шага |
| Вероятность движения ловушки | 0.7 |

Объекты на карте (кодировка наблюдения)

Каждому агенту доступно наблюдение — карта 12×12, где числа обозначают:

| Код | Тип объекта | Описание |
| --- | --- | --- |
| 0 | Туман войны | клетка не видна ни одному союзнику |
| 1 | Пустая клетка | свободное пространство, разведано |
| 2 | Стена | непроходимое препятствие |
| 3 | Этот агент | позиция самого агента |
| 4 | Союзник | другой агент своей команды |

| Код | Тип объекта | Описание |
| --- | --- | --- |
| 5 | Враг | агент противника |
| 6 | Ловушка | смертельная ловушка |

Важно: team_obs строится на основе объединённой видимости всех живых агентов команды. Если хотя бы один союзник видит клетку, она отображается на карте (код > 0). Ловушки и враги видны только в пределах общей видимости команды.

Действия агента

Каждый агент на каждом шаге выбирает одно действие:

| Код | Действие | Описание |
| --- | --- | --- |
| 0 | Движение вверх | переместиться на 1 клетку вверх (row - 1) |
| 1 | Движение вправо | переместиться на 1 клетку вправо (col + 1) |
| 2 | Движение вниз | переместиться на 1 клетку вниз (row + 1) |
| 3 | Движение влево | переместиться на 1 клетку влево (col - 1) |
| 4 | Атака | атаковать врага в соседней клетке |

Система координат: Карта представляет собой матрицу [row, col].

- - Row 0 — верхний край карты, Row 11 — нижний край.

- - Col 0 — левый край карты, Col 11 — правый край.

- - Действие 0 (Вверх) уменьшает индекс строки (row - 1).

- - Действие 2 (Вниз) увеличивает индекс строки (row + 1).

Действие «ожидание» отсутствует. Если агент не может выполнить выбранное движение (стена, занятая клетка), он остаётся на месте и получает штраф.

Важно: Действие «Атака» (код 4), выбранное когда рядом нет врагов, штрафуется (подробнее см. раздел наград). Агент при этом не перемещается и не наносит урон.

Механика боя

1. Атака: если агент выбрал действие 4 и в соседней клетке (4 направления) есть враг, тот теряет 1 HP. Если рядом несколько врагов, атакуется враг с наименьшим HP (при равенстве — первый по порядку).

## 2. Смерть: при HP ≤ 0 агент мгновенно исчезает с карты и больше не может

действовать.

## 3. Ловушка:

- – Если агент оказывается на клетке с ловушкой (путём движения), он немедленно

погибает (HP становится 0).

- – Если ловушка перемещается на клетку, занятую агентом, агент также

мгновенно погибает.

- – Ловушки каждые 2 шага могут перемещаться на одну клетку (с вероятностью

0.7). При перемещении они стремятся к ближайшему агенту (или движутся случайно, если агентов нет).

## 4. Стены: движение в стену или в клетку, занятую другим агентом, невозможно

(действие игнорируется, агент остаётся на месте и получает штраф).

Окончание матча

Матч заканчивается, если выполнено одно из условий: - Все агенты одной команды уничтожены. - Достигнут лимит шагов (200).

Определение победителя: - Если одна команда полностью уничтожена — побеждает другая. - Если по истечении 200 шагов остались живые с обеих сторон, побеждает команда, у которой больше живых агентов. - Если живых поровну — сравнивается суммарное HP живых агентов. - Если и HP равны — объявляется ничья.

Теоретическая справка

Многоагентное обучение с подкреплением (MARL)

Задача относится к классу кооперативных многоагентных систем с частичной наблюдаемостью (Cooperative MARL with Partial Observability). Формально её можно описать как марковскую игру (Markov game). Каждый агент стремится максимизировать ожидаемую суммарную дисконтированную награду:

𝑇 max𝔼 [∑𝛾𝑡 𝑟𝑡] 𝑡=0 где 𝑇 ≤ 200 — максимальная длина эпизода, 𝛾 — коэффициент дисконтирования (обычно 0.95–0.99), а 𝑟𝑡 — награда, полученная на шаге 𝑡.

Роль нейронных сетей в обучении с подкреплением

В отличие от классического обучения с учителем, где для каждого входного примера известна правильная метка (например, класс объекта), в обучении с подкреплением агент учится на собственном опыте взаимодействия со средой. У него нет прямых указаний, какое действие правильно в каждом состоянии. Вместо этого он получает сигнал награды — скалярное значение, которое оценивает качество его действий. Цель агента — максимизировать суммарную накопленную награду за эпизод.

Нейронная сеть в RL выступает в роли аппроксиматора функции, которая связывает состояния среды с действиями. В зависимости от используемого алгоритма сеть может предсказывать:

- • Q-функцию (ценность действия) — ожидаемую суммарную награду, которую агент

получит, если в данном состоянии выполнит определённое действие, а затем будет действовать оптимально. В методе DQN (Deep Q-Network) сеть обучается минимизировать TD-ошибку (Temporal Difference error): ℒ = 𝔼[(𝑟 + 𝛾max 𝑎′ 𝑄(𝑠′, 𝑎′) − 𝑄(𝑠, 𝑎))

] где 𝑄(𝑠,𝑎) — текущая оценка сети для состояния 𝑠 и действия 𝑎, 𝑟 — полученная награда, 𝑠′ — следующее состояние. Разница между «целевым» значением 𝑟 + 𝛾max𝑄(𝑠′,𝑎′) и текущим предсказанием и есть ошибка, которая затем распространяется обратно через сеть, корректируя веса.

- • Политику (вероятности действий) — напрямую выдаёт распределение вероятностей

действий. В методах градиента политики (policy gradient) сеть обновляется в сторону увеличения вероятности действий, которые привели к высокой награде (например, с использованием REINFORCE или PPO).

- • Функцию ценности состояния 𝑉(𝑠) — ожидаемую награду из состояния 𝑠 , что

используется в алгоритмах типа Actor-Critic.

Как награды управляют обучением

На каждом шаге агент получает от среды награду 𝑟𝑡 (которая может быть как положительной, так и отрицательной). Эта награда агрегируется в возврат 𝐺𝑡 = ∑𝑇−𝑡𝑘=0 𝛾𝑘 𝑟𝑡+𝑘. Нейронная сеть настраивается так, чтобы её предсказания (например, 𝑄(𝑠, 𝑎)) как можно точнее соответствовали ожидаемому возврату при выборе действия 𝑎 в состоянии 𝑠.

Процесс обучения итеративен:

## 1. Агент взаимодействует со средой, сохраняя переходы (𝑠,𝑎, 𝑟,𝑠′) в буфер опыта

(replay buffer).

## 2. Случайная выборка из буфера используется для вычисления целевых значений и

функции потерь.

## 3. Градиент функции потерь вычисляется и применяется для обновления весов сети

(обратное распространение).

## 4. Периодически целевая сеть (target network) синхронизируется с основной для

стабилизации обучения.

Таким образом, нейронная сеть постепенно учится предсказывать долгосрочные последствия действий, опираясь только на получаемые награды, без внешних «правильных ответов».

Архитектура Parameter Sharing

Все агенты команды используют единую нейронную сеть с общими весами. Это позволяет эффективно обучать политику на опыте всех трёх агентов одновременно, не увеличивая число параметров. Опыт каждого агента добавляется в общий буфер, и сеть обновляется с учётом всех переходов, что ускоряет сходимость.

Идентификатор агента (agent_id): В наблюдение передаётся agent_id (0, 1, 2).

- - Участник может использовать этот идентификатор как входной признак для

создания специализированных ролей (асимметричная политика).

- - Участник может игнорировать этот идентификатор для создания универсальных

агентов (симметричная политика).

Выбор стратегии зависит от архитектуры решения.

Для эффективного обучения рекомендуется следующая предобработка входных данных:

## 1. One-Hot Encoding для карты наблюдения: Коды объектов (0–6) являются

2. Объединение с скалярными признаками: Скалярные признаки (hp, step, agent_id и т.д.) следует нормализовать (например, разделить на максимальное значение) и объединить с выходом свёрточных слоёв через операцию concat (конкатенацию) перед полносвязными слоями. Пример архитектуры (Референс):

- – Вход карты: 7 каналов (One-Hot) × 12 × 12.

- – Свёрточный блок: 2 слоя Conv2d (32 и 64 фильтра) + MaxPool.

- – Вход скаляров: 5 признаков (нормализованных).

- – Объединение: Flatten карты + Concat со скалярами.

- – Полносвязный блок: MLP (например, 512 → 256 нейронов).

- – Выход: 5 значений (Q-значения для действий).

Комбинирование нейросетевых политик с эвристиками

В практических задачах игрового ИИ часто используется гибридный подход: нейросетевая политика, обученная с подкреплением, дополняется детерминированными эвристиками. Это позволяет объединить адаптивность обучения с гарантированной безопасностью и ускорением принятия решений.

Зачем это нужно:

1. Защита от грубых ошибок: Нейронная сеть может ошибаться даже после обучения, например, предлагать движение в стену или ловушку, если эти объекты видны на карте. Эвристический фильтр может заблокировать такое действие и выбрать безопасную альтернативу (например, случайное допустимое направление или атаку). Это повышает выживаемость агентов в критических ситуациях.

## 2. Ускорение обучения: Сети не нужно тратить ресурсы на изучение очевидных правил

среды (например, «в стены нельзя ходить»), если эти правила уже заложены в эвристику. Это позволяет сконцентрировать вычислительные мощности на освоении сложных тактических приёмов.

## 3. Приоритет важных действий: В некоторых ситуациях эвристика может

переопределять решение сети, чтобы гарантированно достичь тактического преимущества. Например, если враг находится в соседней клетке и имеет всего 1 HP, действие «атака» может быть выполнено безусловно (добивание), даже если сеть предлагает движение.

## 4. Стабильность и надёжность: Эвристики снижают variance поведения, делая

агента менее подверженным случайным сбоям сети.

Рекомендуемые области применения эвристик:

- • Фильтрация действий: перед выполнением действия, предложенного сетью,

проверьте, не приведёт ли оно к столкновению со стеной или ловушкой, если целевая клетка видна в team_obs. Если действие недопустимо, можно:

- – выбрать случайное безопасное направление из доступных;

- – выбрать действие «атака», если оно возможно и есть враг;

- – оставить агента на месте (хотя это может привести к штрафу за застой).

- • Приоритет атаки: если в соседних клетках есть враг с HP=1, и действие «атака»

доступно, можно всегда выбирать атаку, игнорируя выход сети. Это гарантирует устранение угрозы.

- • Избегание ловушек: если в зоне видимости есть ловушка, можно временно повысить

штраф за движение в её сторону (через внутреннюю мотивацию) или явно запретить такие движения. Важно: Полное отсутствие нейросетевой компоненты (чисто эвристическое решение) допускается, но может снизить итоговые баллы за критерии «Стабильность» и «Координация». Эвристики, как правило, не способны адаптироваться к непредвиденным ситуациям и вырабатывать сложные кооперативные стратегии так же эффективно, как обученная сеть. Однако разумное сочетание нейросети и эвристик является стандартной практикой в современных игровых ИИ и позволяет достичь наилучших результатов.

Реализация: Эвристики должны быть реализованы внутри метода choose_action класса Agent в файле solution.py. Они могут анализировать входное состояние и модифицировать выходное действие, полученное от нейросети, или полностью заменять его. Важно, чтобы эвристики не нарушали временные ограничения (не более 0.1 с на вызов) и не использовали информацию, недоступную агенту (например, полную карту).

Функция наград среды Среда возвращает общую командную награду за каждый шаг. Награды предназначены для ускорения сходимости обучения, но не являются прямым критерием оценки решения (см. раздел «Критерии оценивания»).

Полный список наград с точными значениями приведён в файле environment.py. Ключевые события:

| Категория | Примеры событий | Назначение |
| --- | --- | --- |
| Боевые действия | Урон врагу (+2/ед.), убийство (+10), получение урона (–2/ед.) | Стимулирование боя |
| Пустая атака | Попытка атаки без цели (–1.5) | Штраф за бесполезные действия |
| Координация | Совместная атака ≥2 агентов (+5) | Поощрение командной работы |

| Категория | Примеры событий | Назначение |
| --- | --- | --- |
| Навигация | Посещение новых клеток (+2), штраф за стены (–2), штраф за застой (–1) | Исследование карты |
| Итоговые | Победа в матче (+50), поражение (–50) | Глобальная цель |

Важно: Награды среды являются плотными (dense rewards) — агент получает обратную связь на каждом шаге, а не только в конце эпизода. Однако оптимизация под эти награды может не совпадать с турнирными метриками, поэтому рекомендуется использовать внутреннюю мотивацию.

Внутренняя мотивация агента Поскольку файл среды (environment.py) редактировать запрещено, участники могут реализовать дополнительную функцию наград внутри своего агента для лучшей оптимизации под критерии турнира.

Внутренняя мотивация (Intrinsic Motivation) — это дополнительные награды, которые агент генерирует внутри своей архитектуры, независимо от наград среды. Они добавляются к сигналу среды в процессе обучения (но не используются в инференсе).

| Тип внутренней мотивации | Описание | Пример реализации |
| --- | --- | --- |
| Curiosity-driven | Награда за исследование новых состояний | Бонус за посещение клеток с низкой частотой |
| Goal-conditioned | Награда за достижение подцелей | +1 за сближение с врагом, даже без атаки |
| Hierarchical | Награды для разных уровней иерархии | Высокоуровневая политика ставит цели низкоуровневой |
| Reward shaping | Определяемые участником награды в train.py | internal_reward = f(state, action) |

Рекомендации: - Используйте внутреннюю мотивацию для выравнивания наград среды с критериями оценки. - Избегайте конфликта между наградой среды и внутренней наградой (суммируйте их). - Внутренняя мотивация особенно полезна для иерархических архитектур.

Приоритет критериев оценки Обратите внимание: окончательная оценка решения определяется критериями из раздела «Критерии оценивания», а не суммарной наградой от среды.

| Приоритет | Критерий | Вес в итоговой оценке |
| --- | --- | --- |
| 1 | Победы в матчах | 50 баллов |
| 2 | Эффективность боя (kill_diff) | 25 баллов |
| 3 | Координация | 15 баллов |
| 4 | Стабильность | 10 баллов |

Вывод: Оптимизация под награды среды может не привести к победе в турнире. Рекомендуется использовать награды среды как вспомогательный сигнал, а основную оптимизацию проводить под критерии оценки через внутреннюю мотивацию и архитектуру агента.

Локальное тестирование: Для отладки и оценки решения предоставляется скрипт local_tester.py. Он позволяет запускать матчи против встроенного бота-противника (жёлтая команда) и рассчитывает итоговый балл в соответствии с критериями задачи (победы, эффективность боя, координация, стабильность). Бот-противник обладает следующими особенностями:

- - Видит полную карту (без тумана войны).

- - Случайно выбирает одну из стратегий: aggressive, passive, fleeing,

explorer.

- - Принимает решения на основе полной информации, что делает его непредсказуемым

и позволяет проверить адаптивность вашего решения.

Скрипт поддерживает несколько режимов работы и параметров командной строки:

| Параметр | Описание |
| --- | --- |
| --episodes N или -e N | Запустить N эпизодов (матчей) в фоновом режиме без графики. По умолчанию N = 10. По окончании выводится детальная статистика и итоговый балл (0–100). |
| --visualize или -v | Запустить один эпизод с графической визуализацией (требуется установленный pygame). Позволяет наблюдать за поведением агентов в реальном времени. |
| --fullmap или -f | Используется только вместе с --visualize. Отображает полную карту без тумана войны, что полезно для отладки (показывает истинное положение врагов, ловушек и т.д.). |

Примеры использования: # Запустить 100 тестовых эпизодов и получить оценку python local_tester.py --episodes 100

# Запустить один эпизод с визуализацией (стандартный вид) python local_tester.py --visualize

# Запустить визуализацию с отключённым туманом войны python local_tester.py -v -f
