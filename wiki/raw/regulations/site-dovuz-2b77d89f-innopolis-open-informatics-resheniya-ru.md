Innopolis Open по информатике Заключительный тур. 2025-2026 Россия, Иннополис, 14 февраля 2026

Разбор задачи «Забывчивый Шустрик и пульт»

Краткое условие

Есть число A и фиксированное число M. За один шаг можно выполнить одну из операций: A ← A + M, A ← A − M, A ← A · M, A ← A mod M.

Нужно найти кратчайшую последовательность операций, после которой получится число A′, удовлетворяющее

A′ ≡ B (mod N). Если такой последовательности нет, нужно вывести −1.

Система оценки

Баллы за каждую подзадачу начисляются только в случае, если все тесты для этой подзадачи и необходимых подзадач успешно пройдены.

| Группа | Баллы | Доп. ограничения | Необходимые группы |
| --- | --- | --- | --- |
| 1 | 7 | /A/,M,N ⩽ 8 | – |
| 2 | 6 | M = 1 | – |
| 3 | 8 | M = N | – |
| 4 | 12 | M ≡ 0 (mod N) | 3 |
| 5 | 15 | N ≡ 0 (mod M) | 2–3 |
| 6 | 16 | N · M ⩽ 2 · 106 | 1–2 |
| 7 | 18 | A = 0 | – |
| 8 | 18 | – | 1–7 |

Главное наблюдение

Нас интересует не само число A′, а только его остаток по модулю N. Если мы уже используем только операции

+, −, ∗, то все переходы по модулю N определяются однозначно: x → (x + M) mod N, x → (x − M) mod N, x → (x · M) mod N.

Значит, если забыть про операцию %, задача превращается в поиск кратчайшего пути в графе из N вершин, где вершина — это остаток по модулю N.

Почему операция % сильно ограничена

Рассмотрим значение числа по модулю M.

- • Операция + не меняет остаток по модулю M.

- • Операция - не меняет остаток по модулю M.

- • Операция % переводит число в диапазон [0,M − 1], но его остаток по модулю M остаётся тем

же.

- • Операция * зануляет остаток по модулю M, так как

A · M ≡ 0 (mod M).

Отсюда следует:

Пока не было операции *, остаток числа по модулю M всё время равен исходному A mod M. После первой операции * остаток по модулю M становится нулём и уже никогда не меняется.

Теперь посмотрим на операцию %. Она не меняет остаток по модулю M, а просто заменяет число на его наименьшего неотрицательного представителя.

Значит, операция % может быть полезна только для того, чтобы сразу перейти в одно из двух специальных состояний:

- • в число A mod M, если до этого не было операции *;

- • в число 0, если перед этим уже была операция *.

Ключевая лемма о виде оптимального ответа

Лемма. В оптимальной последовательности операция % может встретиться только в одном из трёх случаев:

**1.** её нет совсем;

**2.** она стоит первой;

**3.** перед ней стоит ровно одна операция *, и эта пара имеет вид *%.

Доказательство. Операции + и - не меняют остаток по модулю M, а операция % лишь заменяет число на представитель того же остатка в диапазоне [0,M − 1].

Поэтому если перед операцией % были только операции + и -, то весь этот префикс никак не влияет на результат применения %: после него всё равно получится число

A mod M.

Следовательно, такой префикс можно удалить, и путь станет короче. Значит, если операция % используется до первой *, то она должна стоять первой.

Теперь рассмотрим случай, когда до % уже была операция *. После первой * число становится кратным M, то есть его остаток по модулю M равен нулю. Тогда после % обязательно получится число 0.

Если между этой первой * и % были ещё какие-то операции, то они не меняют остаток по модулю M, а значит после % всё равно получится 0. Следовательно, все такие промежуточные операции можно удалить. Значит, если % используется после появления нулевого остатка по модулю M, то в оптимальном ответе она идёт сразу после первой *, то есть как *%.

Основное решение

Теперь задача полностью сводится к трём возможным стартам:

**1.** начать из A mod N — это случай, когда мы вообще не используем %;

**2.** начать из (A mod M) mod N — это случай, когда первая операция %;

**3.** начать из 0 — это случай, когда первые две операции *%.

После этого остаются только операции +, -, *, которые уже можно рассматривать целиком по модулю N.

Следовательно, для каждого из трёх стартов нужно найти кратчайший путь до остатка B в графе остатков по модулю N.

Граф состояний

Вершины графа:

0,1,2,...,N − 1. Из вершины v есть до трёх переходов:

**1.** v → (v + M) mod N,

**2.** v → (v − M) mod N,

**3.** v → (v · M) mod N. Все рёбра имеют вес 1, значит кратчайший путь ищется обычным BFS.

Разбор задачи «Грандиозное переименование»

Система оценки

| Группа | Баллы | Доп. ограничения | Необходимые группы |
| --- | --- | --- | --- |
| 1 | 14 | n = 1 | – |
| 2 | 17 | sorted(si) = sorted(ti) | – |
| 3 | 25 | si и ti не имеют общих букв | – |
| 4 | 13 | n ⩽ 1000;/si/,/ti/ ⩽ 10 | – |
| 5 | 11 | /si/ = 1, /ti/ = 1 | – |
| 6 | 11 | Все строки состоят из буквы a | – |
| 7 | 9 | – | 1–6 |

Здесь, sorted(si) обозначает отсортированную в алфавитном порядке строку si. Например, sorted(abacaba) = aaaabbc.

Существование ответа

Прежде всего, скажем, что необходимое условие существования ответа: мультимножество букв по всем строкам si должно совпадать с мультимножеством букв по всем строкам ti. Если это не так — ответ −1.

Полное решение получается из решения подзадач 2 и 3, разберём их.

Подзадача 2 (для каждого i: sorted(si) = sorted(ti)):

Заметим, что в оптимальном решении не нужно переносить буквы между разными строками. Действительно, если буква перешла из строки i в строку j, то позднее равная ей буква должна вернуться из некоторого k в i (так как мультимножества совпадают). Но тогда вместо двух этих операций можно было бы сразу сделать перенос буквы из k в j, не увеличив суммарную стоимость. Значит, задача распадается по индексам: для каждого i независимо нужно превратить si в ti операциями вида i = j, каждая из которых стоит 1.

Нужно максимизировать количество букв не участвующих в операциях. Заметим, что такие буквы обязательно образуют общую подпоследовательность строк si и ti. Значит, буквы, которые не нужно трогать — это в точности наибольшая общая подпоследовательность (НОП) строк si и ti. Минимальное число операций равно |si| − |НОП|. НОП находится стандартным динамическим программированием за O(|si| · |ti|).

Подзадача 3 (для каждого i: si и ti не имеют общих букв):

Каждая буква обязана сменить строку хотя бы один раз, при этом более одного перемещения одной буквы заведомо неоптимально. Значит относительное положение буквы внутри каждой строки не имеет значения, и задача распадается на независимые по символам алфавита: для фиксированной буквы c выписываем позиции строк, в которых c встречается в s, и позиции строк, в которых c нужна в t. Их количества совпадают (иначе ответ −1). Нужно разбить их на пары (i,j), минимизируя

(1 + |i − j|).

Оптимальное разбиение достигается в порядке сортировки обоих списков. Это доказывается от обратного, пусть оптимальный ответ другой, тогда есть две пары (i1,j1) и (i2,j2) такие, что i1 < i2 и j1 > j2. В этом случае можно поменять j1 и j2 и суммарная стоимость (2 + |i1 − j1| + |i2 − j2|) не увеличится.

Полное решение:

Для каждой строки i находим НОП(si,ti). Буквы, вошедшие в НОП, остаются на месте. Оставшиеся буквы обрабатываем по символам алфавита независимо: сортируем списки позиций и объединяем в пары в порядке сортировки, суммируя 1 + |i − j|. Итоговая асимптотика: O(n · |si| · |ti| + 26 · n).

Разбор задачи «Расписание олимпиад»

Система оценки

Тесты к этой задаче состоят из тринадцати групп. Баллы за каждую группу ставятся только при прохождении всех тестов группы и всех тестов необходимых для неё групп.

| Группа | Баллы | Доп. ограничения | Необходимые группы |
| --- | --- | --- | --- |
| 1 | 10 | n,D ⩽ 20; bi ⩽ 20 для всех i; t = 1 | – |
| 2 | 7 | n,D ⩽ 20; bi ⩽ 20 для всех i | 1 |
| 3 | 11 | n,D ⩽ 100; bi ⩽ 100 для всех i | 1, 2 |
| 4 | 9 | n,D ⩽ 800; bi ⩽ 800 для всех i | 1, 2, 3 |
| 5 | 5 | n,D ⩽ 2500; bi ⩽ 2500 для всех i; t = 1 | 1 |
| 6 | 4 | n,D ⩽ 2500; bi ⩽ 2500 для всех i | 1–5 |
| 7 | 5 | bi = bj для всех i, j | – |
| 8 | 5 | di = dj для всех i и j, таких что i = j | – |
| 9 | 5 | di = 1 для всех i; t = 1 | – |
| 10 | 5 | di = dj для всех i, j | 9 |
| 11 | 8 | D ⩽ 2 · 106 | 1–6 |
| 12 | 10 | t = 1 | 1, 5, 9 |
| 13 | 16 | – | 1–12 |

̸ ̸

Общая идея

Заметим, что:

**1.** В каждый день имеет смысл оставить только одну олимпиаду, дающую максимальную пользу среди всех, поставленных в этот день. Остальные олимпиады в этот день можно “спрятать” (перенести в другой день или оставить, но они не повлияют на пользу).

**2.** Задача сводится к выбору не более D олимпиад и распределению их по различным дням (по одной на день) с сохранением порядка и ограничений на даты.

**3.** Невыбранные олимпиады можно разместить в любые дни (не нарушая порядок), но они не дадут вклада в ответ.

Группа 1 (10 баллов) n,D ⩽ 20, bi ⩽ 20, t = 1

Решение: Переберем все 2n подмножеств олимпиад, которые могут дать пользу. Для фиксированного подмножества размера k нужно проверить, можно ли разместить эти олимпиады в k различных днях.

Проверка: Будем размещать выбранные олимпиады жадно слева направо: очередную олимпиаду поставим в самый левый допустимый для неё день.

Сложность: O(2n · n).

Группа 2 (7 баллов) n,D ⩽ 20, bi ⩽ 20

Решение: Дополняем подход из группы 1: после выбора подмножества “полезных” олимпиад нужно разместить все олимпиады. Перебираем олимпиады, ставим очередную в самый левый допустимый для неё день. Сложность: O(2n · n).

Группы 3-4 (20 баллов) n,D ⩽ 800, bi ⩽ 800

Решение: Динамическое программирование: dp[i][d] — максимальная польза для первых i олимпиад, если мы рассмотрели первые d дней (т.е. все олимпиады размещены в дни ⩽ d, а дни > d еще не использовались).

Переход: Рассматриваем i-ю олимпиаду. Перебираем день x от max(di,d) до D, куда ее поставим: dp[i + 1][x] = max(dp[i + 1][x], dp[i][d] + bi) Если олимпиаду не учитываем в ответе, то просто переходим в состояние i + 1,d.

Сложность: O(n · D2).

Группы 5-6 (9 балла) n,D ⩽ 2500, bi ⩽ 2500 Решение (для групп 5–6): Более эффективное ДП с двумя типами переходов: Состояние dp[i][d] — максимальная польза для первых i олимпиад, если мы рассмотрели первые d дней, и день d уже закрыт (т.е. мы больше не можем ставить учтённые олимпиады в день d). Переходы:

**1.** Олимпиада i ставится в день d (и не учитывается): dp[i + 1][d] = max(dp[i + 1][d],dp[i][d])

**2.** Ставим i-ю олимпиаду в день d + 1: dp[i + 1][d + 1] = max(dp[i + 1][d + 1],dp[i][d] + bi) (при условии d + 1 ⩾ di)

**3.** Пропускаем день d (олимпиада i ставится позже): dp[i][d + 1] = max(dp[i][d + 1],dp[i][d]) Сложность: O(n · D).

Группа 7 (5 баллов)

Все bi равны

Решение: Так как все пользы одинаковы, задача сводится к максимизации количества дней, в которых есть хотя бы одна олимпиада. Жадность: идем по дням от 1 до D. Для каждого дня пытаемся найти самую левую из еще не размещенных олимпиад, которую можно поставить в этот день (т.е. di ⩽ текущий день). Если находим — ставим, иначе день остается пустым. Это максимизирует количество занятых дней.

Достаточно рассмотреть последние n дней. Сложность: O(n + D).

Группа 8 (5 баллов)

Все di различны

Решение: Оставим каждую олимпиаду на ее исходной дате. Тогда все дни заняты разными олимпиадами, и суммарная польза = bi.

Сложность: O(n).

Группа 9 (5 баллов)

Все di = 1, t = 1

Решение: Все олимпиады изначально в день 1. Мы можем сдвинуть их на любые дни ⩾ 1. Нам нужно выбрать min(n,D) олимпиад (по одной на день) с максимальной суммарной пользой. Берем min(n,D) олимпиад с максимальной пользой (при равенстве пользы — любые). Расставляем их в порядке номеров по дням 1,2,....

Сложность: O(nlog n).

Группа 10 (5 баллов)

Все di равны (общая дата d0)

Решение: Доступные дни: от d0 до D, всего D − d0 + 1 дней. В каждый такой день можно поставить не более одной олимпиады. Выбираем min(n,D−d0+1) олимпиад с максимальной пользой и расставляем в порядке номеров.

Сложность: O(nlog n).

Группы 11-13 (16 баллов)

Без дополнительных ограничений

Полное решение (жадность с конца):

**1.** Будем идти по дням от D до 1.

**2.** Поддерживаем активное множество олимпиад, которые мы планируем учесть в ответе, и структуру данных для быстрого извлечения минимальной пользы (например, min-heap).

**3.** Для текущего дня j добавляем в активное множество все олимпиады с di ⩽ j (их можно перенести в день j или позже).

**4.** Если в активном множестве больше элементов, чем осталось дней (включая текущий), удаляем из него олимпиаду с наименьшей пользой (она не войдет в ответ).

**5.** После прохода всех дней в активном множестве останутся олимпиады, которые дадут максимальную пользу.

Почему это работает: На каждом шаге мы гарантируем, что для оставшихся дней (с конца) есть достаточно места, чтобы разместить все выбранные олимпиады в порядке номеров. Удаление наименее полезной олимпиады оптимально, так как если нужно освободить место, лучше пожертвовать олимпиадой с наименьшей пользой.

Сложность: O((n + D)log n). Примечание: В данном решении мы сначала оставили только ограничение об относительном порядке и проигнорировали второе ограничение (ограничение на неуменьшение дат), а затем верну-ли его (стали игнорировать лишние олимпиады с минимальной полезностью). Возможно и обратное — оставить только ограничение на неуменьшение дат. Тогда жадное решение (идти слева направо и ставить олимпиаду с максимальной полезностью) даст нам только набор олимпиад, но не сохранит относительный порядок. Останется лишь посортировать выбранные олимпиады по номеру и расставить их в последние k дней.

Разбор задачи «Башня из коробок»

Система оценки

В этой задаче тесты двух видов. Тест первого вида — генерируется массив [1, 1, 2, 2, ..., N, N] и случайным образом перемешивается, получается массив [a1,a2,...,aT] размера T, T = 2N. Тогда очередная коробка добавляется в момент времени t1 и достаётся в момент времени t2, если t1 < t2 и a[t1] = a[t2].

Тест второго вида — гарантируется, что коробки достаются в том же порядке, в котором добавляются.

Для каждого значения N (числа коробок) сгенерировано по одному тесту каждого вида.

| --- | --- | --- | --- | --- | --- |
| 1 | 1-2 | Тесты из условия | 0 за тест | 0 | - |
| 2 | 3-10 | 100, 200, 330, 420 | 1 за тест | 8 | - |
| 3 | 11-18 | 480, 720, 820, 1080 | 1 за тест | 16 | 1 |
| 4 | 19-26 | 1240, 1420, 1630, 1870 | 1 за тест | 24 | 1-2 |
| 5 | 27-30 | 2150, 2470 | 1 за тест | 28 | 1-3 |
| 5 | 31-34 | 2840, 3260 | 2 за тест | 36 | 1-3 |
| 6 | 35-42 | 3740, 4300, 4940, 5680 | 2 за тест | 52 | 1-4 |
| 7 | 43-50 | 6530, 7500, 8620, 9910 | 2 за тест | 68 | 1-5 |
| 8 | 51-58 | 11390, 13090, 15050, 17300 | 2 за тест | 84 | 1-6 |
| 9 | 59-66 | 17500, 18000, 18500, 19000 | 2 за тест | 100 | 1-7 |

Одно из возможных решений

Одно из самых простых решений — новый предмет размещать всегда наверху стека, а при извлечении предмета — собирать все блокирующие его извлечение предметы в буфер, извлекать предмет и возвращать предметы из буфера в стек в отсортированном порядке — чем раньше извлекается предмет, тем выше в стеке мы его расположим. Такое решение не всегда будет оптимальным, например, из состояния стека [...,2,1,3,4] (здесь самый правый элемент — наверху стека) перейдём в состояние [...,2,4,3] при извлечении предмета с номером 1. Затем при извлечении предмета с номером 2 предметы 3,4 будут повторно помещены в буфер. Видно, что если изначально вместе с предметом 1 достать ещё один, следующий предмет — 2, суммарное число операций уменьшится. А именно от состояния стека [...,2,1,3,4] мы перейдём к состоянию [...,4,3,2], после чего извлечём каждый из предметов за одно действие сверху стека. В этом случае предметы 2,3,4 по одному разу окажутся в буфере и число действий сократится.

Оценка на число действий

Рассмотрим пример — пусть N предметов приходит и уходит в порядке очереди, при этом размер очереди равен T. А именно в момент времени 2i появляется элемент со значением ti = i + 2T + 1. Тогда с момента времени 2T предметы по очереди размещаются и извлекаются из стека.

Обозначим число элементов, снятых со стека в момент i как ai. Заметим, что число моментов времени, когда ai ⩾ q для любого целого q < T не меньше чем (N − T)/q. Докажем это.

Допустим q шагов подряд значение ai не превосходит q (за шаг считаем извлечение предмета и затем размещение нового предмета). Тогда элемент x, который необходимо будет извлечь в момент сразу после этих q шагов будет хотя бы на глубине q в стеке по той причине, что в верхних q элементах стека с каждым новым размещением появляется один элемент, больший x (причём на каждом шаге один элемент из верхних q заменяется на новый, и никакой элемент не мог сначала заменить, а затем замениться, следовательно заменились все элементы и не осталось элементов ⩽ x). Значит на следующем шаге, чтобы получить доступ к элементу x и извлечь его необходимо потратить хотя бы q + 1 действие.

Рассмотрим значения q = 2m для всех 2m < T. Тогда для каждого такого значения q будет хотя бы N/(q + 1) моментов времени таких, что ai ⩾ q. При этом один момент времени будет учтён несколько раз (для разных значений q). Тогда каждому значению m приведём в соответствие

(N/2m − N/2m+1) моментов времени, начиная с m = log2 T и заканчивая m = 1, каждый раз исключая моменты времени уже занятые до этого. Получим что суммарно действий было совершено порядка log T

N 2m+1 · 2m.

N log T ≈ m=1

При этом приведённая асимптотическая оценка совпадает с верхней оценкой на число действий — далее приведём решение, которое для произвольных значений времени извлечения выполнит не более O(N log T) действий, где T — наибольшее число элементов, которое хранится в стеке одновременно (если этот параметр известен заранее).

Решение за O(N log T) действий

Будем считать число событий (появление нового элемента для размещения и извлечение очередного элемента), произошедших с начала работы алгоритма. Тогда после события j для наибольшей степени двойки m, такой что 2m | j (то есть j делится нацело на 2m) достанем из стека min(2 · 2m,|S|) элементов и вернём обратно в порядке убывания времени извлечения.

Лемма: Перед действием в момент j следующие min(2m,|S|) по времени извлечения предметов (не учитывая ещё не поступившие в стек) находятся среди верхних 2 · 2m элементов стека.

Доказательство: Докажем по индукции по j. База индукции: для j = 0 в стеке находится нулевое количество элементов, для них утверждение леммы выполняется.

Переход. Заметим что после обработки события j − 2m утверждение выполняется (так как j − 2m < j) по предположению индукции. 2m+1 | j − 2m, а значит min(2 · 2m+1,|S|) минимальных по времени извлечения элементов упорядочены и находятся наверху стека после обработки события j − 2m.

Пусть среди событий [j − 2m,j) было r извлечений и 2m − r размещений. Каждое извлечение забирает минимальный элемент из верхних 2 · 2m, каждое размещение сдвигает самый поздний из верхних элементов вглубь стека. Тогда перед обработкой события j в верхних 2 · 2m элементах осталось хотя бы

2 · 2m − 2m = 2m минимальных элементов, минимальных по времени извлечения, что равно требуемому количеству min(2m,|S|).

Краткое условие

Поддерживается динамическое мультимножество строк. После каждой операции добавления или удаления строки нужно найти минимальное число действий, необходимое, чтобы сделать все строки одинаковыми.

Разрешённые действия над одной строкой:

- • удалить последний символ;

- • дописать любой символ в конец.

Строка, к которой мы приводим все остальные, может быть любой, в том числе пустой.

Наблюдение 1: переход к дереву-префиксов

Построим бор по всем строкам, которые вообще встречаются во входных запросах. Корень соответствует пустой строке, каждая вершина — некоторому префиксу, а глубина вершины равна длине соответствующей строки.

Каждая строка из мультимножества теперь отождествляется с вершиной бора. Если мы хотим превратить строку s в строку t, то:

- • нужно удалить из s суффикс после их наибольшего общего префикса;

- • затем дописать недостающий суффикс строки t.

Поэтому число действий равно

|s| + |t| − 2 · |LCP(s,t)|.

Но именно так выглядит расстояние между двумя вершинами в боре. Значит, стоимость приведения строки s к строке t равна расстоянию между соответствующими вершинами дерева.

Итак, задача сводится к следующей:

Есть дерево (бор), в некоторых вершинах лежат активные фишки с кратностями. После каждого добавления/удаления фишки нужно найти вершину v, минимизирующую сумму расстояний до всех активных фишек.

Почему достаточно рассматривать только вершины бора

В условии разрешено приводить все строки к любой строке, даже если её нет в мультимножестве. Но достаточно рассматривать только вершины бора.

Действительно, если целевая строка не является префиксом ни одной строки, встречающейся во входе, то соответствующей вершины в боре нет. Тогда последняя буква этой строки ведёт в поддерево, в котором нет ни одной активной строки. Если сдвинуть цель на один символ вверх, расстояние до каждой активной строки не увеличится, а на самом деле уменьшится на 1. Значит, оптимальная цель всегда является вершиной бора, построенного по всем строкам запросов.

Наблюдение 2: оптимальная вершина — медиана дерева Пусть в дереве выбрана вершина v, а суммарная стоимость равна

F(v) = dist(u,v), u активна где строки учитываются с кратностями.

Рассмотрим переход из вершины v в её соседа to. Пусть в компоненте, которая содержит to после удаления ребра (v,to), лежит x активных строк, а всего активных строк M.

Тогда:

- • для этих x строк расстояние уменьшится на 1;

- • для остальных M − x строк расстояние увеличится на 1.

Следовательно,

F(to) − F(v) = (M − x) − x = M − 2x. Отсюда немедленно следует критерий оптимальности. Лемма. Вершина v минимизирует сумму расстояний до всех активных строк тогда и только тогда, когда после удаления v каждая компонента содержит не более половины всех активных строк.

Доказательство. Если в некоторую компоненту уходит больше половины активных строк, то переход в эту сторону уменьшает ответ, так как M − 2x < 0. Если же во всех компонентах не более половины, то переход в любую сторону ответ не улучшает.

Это обычная взвешенная медиана дерева.

Как найти медиану в корневом дереве

Зафиксируем корень бора в пустой строке. Пусть всего активных строк M. Тогда медиана — это вершина, в которой:

- • ни одно поддерево сына не содержит более M/2 активных строк;

- • при этом выше подниматься уже нельзя, иначе мы попадём в компоненту “всё остальное”,

содержащую больше половины.

Эквивалентно: если идти от корня вниз, то пока существует сын, чьё поддерево содержит строго больше половины всех активных строк, нужно идти в него. Остановимся мы ровно в медиане.

То есть медиана — это самая глубокая вершина, чьё поддерево содержит больше половины всех активных строк.

После того как медиана найдена, нужно посчитать dist(u,med). u активна

Для этого используем стандартную динамику на центроидном дереве.

Что хранится в центроидном дереве Построим центроидное дерево на боре.

Для каждой вершины-центроида c будем хранить:

- • cnt[c] — сколько активных строк учтено в структурах этого центроида;

- • sum[c] — сумма расстояний от всех активных строк до c.

Кроме того, для каждого центроида x (кроме корня центроидного дерева) храним информацию о той части, которая соответствует его компоненте относительно родителя по центроидному дереву:

- • subcnt[x] — сколько активных строк лежит в этой части;

- • subsum[x] — сумма расстояний от этих строк до родителя x в центроидном дереве.

Обновление

При добавлении или удалении активной строки в вершине v поднимаемся по всем центроидам на пути от v к корню центроидного дерева. Для каждого такого центроида c:

- • меняем cnt[c];

- • меняем sum[c] на ±dist(v,c).

А для центроидного сына, через которого мы пришли вверх, обновляем также subcnt и subsum. Число таких центроидов равно O(log N).

Запрос

Для произвольной вершины v сумма расстояний до всех активных строк считается так же стандартно.

Поднимаемся по пути v к корню центроидного разложения. Для каждого центроида c:

- • прибавляем

sum[c] + cnt[c] · dist(v,c), что соответствует всем активным строкам, учтённым в c;

- • но часть строк, лежащих в том же центроидном поддереве, что и v, посчитана лишний раз,

поэтому её нужно вычесть с помощью subcnt и subsum.

В итоге за O(log N) верно вычисляется сумма расстояний от v до всех активных строк.

Полное решение

Сразу приведём полное решение. Задача сводится к следующей формулировке: дано дерево, все вершины которого изначально белые. Рассматривается процесс, в котором некоторые вершины последовательно перекрашиваются в чёрный цвет. После каждого шага в каждой белой вершине записано число её чёрных соседей. Требуется определить максимальное число вершин, которое можно покрасить в некотором порядке так, чтобы после каждого из этих шагов XOR всех значений в белых вершинах был равен нулю. Если это максимальное число равно k, то ответ задачи равен k + 1.

Опишем изменение XOR после покраски одной вершины. Пусть в некоторый момент красится белая вершина v. Через t обозначим число её чёрных соседей в этот момент. До покраски значение t входило в общий XOR, поскольку вершина v была белой. После покраски вершина v перестаёт учитываться. Для каждого белого соседа u вершины v значение в вершине u увеличивается на единицу, то есть изменяется с au на au + 1. Следовательно, общий XOR изменяется на величину t ⊕ au ⊕ (au + 1) . u — белый сосед v

Следовательно, если до рассматриваемого шага XOR был равен нулю, то после него он останется равным нулю тогда и только тогда, когда величина изменения XOR равна нулю.

Введём обозначение

∆(x) = x ⊕ (x + 1). Тогда условие корректности покраски вершины v принимает вид t =

∆(au). u — белый сосед v

Рассмотрим значения функции ∆(x). Для любого x число ∆(x) имеет вид 2k −1. Это следует из двоичного представления: при переходе от x к x + 1 меняется конечный суффикс битов, поэтому в XOR возникает последовательность подряд идущих единиц. Например,

0 ⊕ 1 = 1, 1 ⊕ 2 = 3, 2 ⊕ 3 = 1, 3 ⊕ 4 = 7.

Следовательно, если у фиксированной белой вершины число чёрных соседей последовательно увеличивается с 0 до 1, затем с 1 до 2, затем с 2 до 3 и так далее, то возникающие метки образуют последовательность

1,3,1,7,1,3,1,15,1,3,1,7,1,3,1,31,...

Таким образом, каждый раз, когда красится очередной сосед фиксированной вершины, в условии сохранения нулевого XOR появляется одна из указанных меток.

Для фиксированной вершины эта последовательность определяется исключительно числом уже покрашенных соседей. Если у вершины уже покрашено k соседей, то множество использованных меток совпадает с первыми k членами указанной последовательности. Поэтому существенной является только длина соответствующего префикса.

Назовём состояние вершины префиксным, если оно соответствует первым k элементам последовательности

1,3,1,7,1,3,1,15,... для некоторого k. В реализации такое состояние кодируется количеством уже использованных меток каждого типа. При ограничении n ⩽ 369 достаточно учитывать только метки

1,3,7,15,31.

Докажем это. Пусть c[k] обозначает минимальное число вершин в дереве, необходимое для существования корректной конфигурации, в которой некоторая белая вершина имеет ровно k чёрных соседей. Для перехода от k − 1 к k требуется покрасить ещё одного её соседа. При этом возникает метка

(k − 1) ⊕ k = 2x − 1

Чтобы после такого шага общий XOR снова стал равен нулю, внутри поддерева нового соседа должна существовать конфигурация, компенсирующая именно эту метку. Минимальное число вершин, необходимое для этого, не меньше c[2x − 1]. Следовательно, c[k] ⩾ c[k − 1] + c[2x − 1].

Из базовых значений c[1] = 1, c[2] = 3, c[3] = 7 и этой рекуррентной оценки следует, что уже c[63] > 369. Следовательно, метка 63 и все большие метки не могут появиться ни в одной допустимой конфигурации при заданных ограничениях. Поэтому достаточно рассматривать только метки 1,3,7,15,31.

Задача решается динамикой по дереву. Корень выбирается произвольно. Для каждой вершины v рассматривается её поддерево. Относительно родителя существуют два случая: вершина v покрашена раньше родителя либо после него. Случай, когда вершина v не покрашивается в рассматриваемом хорошем префиксе, включается во второй случай.

Состояние before_parent[l] означает, что вершина v покрашена раньше родителя, а в момент её покраски увеличение числа чёрных соседей у родителя создаёт метку l. Иными словами, из поддерева вершины v вверх передаётся метка l. Значение этого состояния равно максимальному числу покрашенных вершин в поддереве v, достижимому при указанном условии.

Состояние after_parent[l] означает, что родитель покрашен раньше вершины v. При этом либо вершина v будет покрашена позднее и тогда в момент своей покраски передаст наверх метку l, либо вершина v не будет покрашена в рассматриваемом хорошем префиксе. Частный случай l = 0 соответствует отсутствию вклада наверх. Значение этого состояния также равно максимальному числу покрашенных вершин в поддереве v.

Рассмотрим сначала случай, когда вершина v остаётся белой. Тогда для каждого её ребёнка существуют два допустимых варианта. В первом варианте ребёнок к этому моменту также не покрашен; тогда соответствующее дочернее поддерево должно находиться в состоянии after_parent[0]. Во втором варианте ребёнок покрашен раньше вершины v; тогда он использует некоторую метку l из префиксной последовательности вершины v, а его поддерево должно находиться в состоянии before_parent[l]. После последовательной обработки детей формируется некоторое префиксное состояние вершины v, то есть фиксируется, какие первые метки последовательности 1,3,1,7,... уже реализованы её ранее покрашенными детьми. Для каждого такого состояния хранится максимум числа покрашенных вершин в уже обработанной части поддерева.

Рассмотрим случай, когда вершина v сама покрашена. Тогда её дети разбиваются на две группы. К первой группе относятся дети, покрашенные раньше вершины v; они образуют некоторое префиксное состояние, обозначим его через s. Ко второй группе относятся дети, которые в момент покраски вершины v ещё белые; они либо будут покрашены позже, либо не будут покрашены вовсе.

Пусть префиксное состояние s соответствует множеству детей вершины v, которые уже покрашены к моменту покраски v. Тогда число таких детей однозначно определяется состоянием s. Обозначим его через total(s). Поскольку к этому моменту родитель и остальные дети вершины v ещё не покрашены, число чёрных соседей вершины v в момент её покраски равно именно total(s).

Рассмотрим теперь остальных детей вершины v, то есть тех, которые в момент её покраски ещё остаются белыми. Каждый такой ребёнок даёт вклад в условие корректности покраски v через соответствующую метку. XOR всех этих вкладов обозначим через x.

Тогда условие корректности покраски вершины v формулируется следующим образом. Если родитель вершины v в этот момент отсутствует или не даёт дополнительного вклада, то суммарный вклад от ещё белых детей должен совпадать с числом уже покрашенных детей, то есть должно выполняться равенство x = total(s).

Если же вершина v красится раньше родителя и при этом наверх передаётся метка l, то эта метка также участвует в балансе, и условие принимает вид x = l ⊕ total(s).

Следовательно, для уже покрашенной вершины v достаточно хранить два параметра: префиксное состояние s, задающее детей, покрашенных раньше вершины v, и значение x, равное XOR вкладов детей, остающихся белыми в момент её покраски. При обработке очередного ребёнка возможны два случая. Если этот ребёнок покрашен раньше вершины v, то его поддерево должно находиться в состоянии before_parent[l], а метка l добавляется в префиксное состояние. Если этот ребёнок к моменту покраски вершины v ещё белый, то его поддерево должно находиться в состоянии after_parent[l], а метка l XOR-ится в величину x. После обработки всех детей остаётся проверить одно из указанных выше равенств; если оно выполнено, то покраска вершины v допустима.

Теперь опишем переходы. Для вычисления after_parent[0] рассматриваются все допустимые префиксные состояния детей в случае, когда вершина v остаётся белой. Среди них выбирается максимум по числу покрашенных вершин.

Для вычисления after_parent[l] при l ̸= 0 используется следующее условие. Метка l впоследствии должна быть передана от вершины v к родителю, следовательно, она должна входить в допустимый префикс последовательности вершины v. Эта метка резервируется для связи с родителем, а остальные метки префикса формируются детьми. После этого рассматриваются два случая: вершина v остаётся белой либо вершина v покрашивается; во втором случае дополнительно проверяется условие баланса между уже покрашенными и ещё белыми детьми.

Для вычисления before_parent[l] вершина v обязана быть покрашена раньше родителя. Если дети, покрашенные раньше неё, образуют префиксное состояние s, то у вершины v уже имеется total(s) чёрных соседей снизу, а вклад l соответствует родителю. Следовательно, XOR вкладов от детей, не покрашенных к моменту покраски вершины v, должен быть равен l ⊕ total(s).

Среди всех состояний s, для которых это условие выполнимо, выбирается максимум. Корректность динамики доказывается индукцией по поддереву. Для листа утверждение очевидно, поскольку детей у него нет и все состояния вычисляются непосредственно. Предположим, что для всех детей вершины v значения состояний before_parent и after_parent вычислены корректно. Рассмотрим допустимую конфигурацию хорошего префикса внутри поддерева вершины v. Для каждого ребёнка относительно вершины v возможен ровно один из трёх вариантов: ребёнок покрашен раньше вершины v, позже неё или не покрашен вовсе. Следовательно, поведение каждого дочернего поддерева полностью задаётся одним из состояний before_parent[l] или after_parent[l]. При объединении детей на вершине v существенными являются только две характеристики: префиксное состояние, образованное детьми, покрашенными раньше вершины v, и XOR меток от детей, остающихся белыми в момент её покраски. Дополнительная информация о внутреннем устройстве дочерних поддеревьев для проверки корректности не требуется. Следовательно, переходы динамики перебирают все допустимые конфигурации без потерь. Поскольку в каждом состоянии выбирается максимум по числу покрашенных вершин, получаются корректные оптимальные значения состояний для вершины v. По индукции утверждение верно для всех вершин дерева, в том числе для корня.
